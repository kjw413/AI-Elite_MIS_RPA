# DB_에너지 0 기록 원인 조사 — 2026-09-18

## 결론

9월 17일부터 생산실적 RPA가 요청한 월 누계 기간 대신 마지막 하루 데이터만 수집했다. 에너지 가공은 수집하지 않은 날짜를 무생산 0으로 간주하고, 그 값을 정상 이력이 남아 있는 생산 DB보다 우선 적용했다. 이 결합으로 기존 에너지 생산량이 0 또는 과소 값으로 덮어써졌다. 생산량이 0이 된 행의 원단위는 기존 `IFERROR(...,0)` 수식에 의해 0으로 계산됐다.

데이터를 0으로 만든 코드 경로와 발생 시점은 로그·백업·현행 파일 대조로 확인했다. MIS가 마지막 하루만 반환하게 된 구체적인 화면 동작 원인(날짜 필드 포커스·TAB 이동·입력값 자동 보정 등)은 로그만으로 확정할 수 없다. 현행 코드는 입력 키를 보냈다는 사실만 기록하고 실제 날짜 필드 값을 재조회하지 않는다.

운영 엑셀, 운영 코드, MIS 화면은 변경하지 않았다. 이 보고서와 조사 스크립트/JSON/노트북만 프로젝트 analysis 폴더에 생성했다.

## 코드상 원인

1. `production_daily_rpa.py:513`의 `set_date_range()`는 시작일 필드를 좌표 클릭하고, `:532`에서 TAB으로 종료일 포커스 이동을 가정한다. 실제 종료일 클릭 좌표는 설정에 존재하나 이 함수에서는 사용하지 않는다. 입력 후 두 필드의 실제 값 검증이 없다.
2. `production_daily_rpa.py:791`에서 실제 반환 데이터 범위와 무관하게 요청한 시작·종료일을 `__PERIOD__`로 기록한다. 실제 데이터가 하루여도 월 전체 수집으로 표시된다.
3. `energy_builder.py:425~449`는 그 기간 내에 없는 날짜를 `actuals.setdefault(..., 0.0)`으로 채운다. 정상 무생산일 생략을 처리하기 위한 로직이지만 불완전 수집도 0으로 바꾼다.
4. `energy_builder.py:688`의 `actuals.update(...)`가 정상 `DB_생산실적.xlsx` 집계를 위 0 값으로 덮어쓴다.
5. `energy_builder.py:939~943`에서 그 결과를 `DB_에너지.xlsx` N열에 저장한다. 기존 원단위 수식 예: 남양주1 Q976 = `IFERROR(D976*1000/$N976,0)`. N976이 0이므로 원단위도 0으로 저장된다. 단순 표시/캐시 누락 현상이 아니다.
6. 광주는 그 뒤 재공품 DB 환산 합계를 더하므로 일부 생산량이 남지만 일반 생산실적 기여분이 사라진다.

로그가 성공으로 끝나는 이유: 0 값에도 공장·일자 키가 존재하므로 '생산실적 없음' 검사에 걸리지 않는다. `write_raw()`에서 이미 잘못 덮어쓴 다음 `resync_production()`이 같은 계산값과 재비교하므로 '생산량 변경 0건 / 실적 없음 0건'이 찍힌다. 이 문구는 가공 전 데이터에 변화가 없었다는 뜻이 아니다.

## 복구 및 재발 방지 방향

1. 생산실적 화면에서 시작일과 종료일을 각각 확실하게 입력하고 실제 표시값을 읽어 요청기간과 대조한다. TAB 가정을 없애는 것만으로 완료로 보지 않고 실제 수집 헤더 및 누계값까지 확인한다.
2. 기존에 비영 생산실적이 있던 여러 날짜 열이 한 번에 사라지는 수집 결과는 가공 전에 중단·격리한다. MIS가 정상 무생산일을 생략할 수 있으므로 모든 달력 날짜 열을 무조건 요구하는 검증은 피한다.
3. 검증되지 않은 수집 누락은 0 대신 미수집으로 구분하고, 검증된 범위·값만 생산 DB에 우선 적용한다. 0으로 실제 정정된 경우도 별도로 처리할 수 있어야 한다.
4. 9/1~17 생산 원본을 정상 재수집한 뒤 에너지를 재가공한다. 보존된 생산 DB와 광주 재공품을 이용한 재생성도 가능하지만, 현행 가공 명령을 그대로 실행하면 잘못된 RawDB의 0이 다시 우선 적용된다.
5. 복구 시 81개 불일치가 해소되는지, B:M 수집값과 9/1 이전 이력이 보존되는지, 원단위 수식이 재계산되는지 대조한다. 9/17 직전 에너지 백업을 통째로 덮으면 이후 9/16~17 데이터와 재공품 정정이 빠질 수 있다.

현재는 원인 조사만 수행했으며 복구 또는 운영 코드 수정은 실행하지 않았다.
